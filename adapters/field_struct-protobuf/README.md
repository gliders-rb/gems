# field_struct-protobuf

> Preview: `1.0.0.pre1`. The API is settled by the specs, but nothing here has had a release yet.

Protocol Buffers for [field_struct](../../gems/field_struct) classes, and no `protoc` run to set up. From one class you can
print `.proto` source for other teams, get a message class registered with `google-protobuf`, and move instances between
structs, messages and wire bytes.

Field numbers are yours: every field says `proto: {number: n}`. Numbering by declaration order would make reordering a silent
wire-format break, so the gem never guesses. Anything without an exact mapping (a union, an array of arrays, a custom type)
raises `ArgumentError` naming the class and field, never a lossy default. It does not validate (`format:`, `in:`), and it
builds proto3 only: no `oneof`, enums, maps, services or options.

## Install

```ruby
gem 'field_struct-protobuf'
```

```ruby
require 'field_struct/protobuf'
```

## Quick start

<!-- doctest -->
```ruby
require 'field_struct/protobuf'

module Velo
  class Bike < FieldStruct::Base
    required :id,    :uuid,        proto: {number: 1}
    required :fare, :big_decimal, round: 2, proto: {number: 2}
    required :started, :time,        zone: 'America/Denver', proto: {number: 3}
    required :grade, :symbol,      enum: %i[standard electric], proto: {number: 4}
    optional :labels,  :array,       of: :string, proto: {number: 5}
  end
end

bike = Velo::Bike.new(id: '3f6f2c3e-1111-4222-8333-444455556666', fare: '19.9',
                         started: Time.utc(2026, 10, 27, 15, 30), grade: :electric, labels: %w[commuter])

bytes = FieldStruct::Protobuf.encode(bike)
bytes.encoding # => #<Encoding:BINARY (ASCII-8BIT)>
FieldStruct::Protobuf.decode(Velo::Bike, bytes) == bike # => true
FieldStruct::Protobuf.decode(Velo::Bike, bytes).started.utc_offset # => -21600
```

## The `.proto` text

`proto` prints the file for one class. The text is printed from the descriptor that gets registered, so the two cannot
disagree; compiling it with `protoc` gives an equivalent descriptor.

<!-- doctest -->
```ruby
require 'field_struct/protobuf'

module Velo
  class Station < FieldStruct::Base
    required :district, :string, proto: {number: 1}
    optional :dock,  :string, proto: {number: 2}
  end
end

print FieldStruct::Protobuf.proto(Velo::Station)
FieldStruct::Protobuf.proto(Velo::Station).lines.last(4).join # => "message Station {\n  optional string district = 1;\n  optional string dock = 2;\n}\n"
FieldStruct::Protobuf.file_name(Velo::Station) # => "field_struct/velo/station.proto"
FieldStruct::Protobuf.full_name(Velo::Station) # => ".velo.Station"
```

It prints:

```proto
// field_struct/velo/station.proto: generated by field_struct-protobuf from Velo::Station.
// Field numbers come from each field's proto: {number:} option.

syntax = "proto3";

package velo;

message Station {
  optional string district = 1;
  optional string dock = 2;
}
```

One file per class, one message per file. A struct's file imports the files of the structs it refers to; a struct may refer to
itself, but two structs may not refer to each other.

## Type mapping

| FieldStruct type | Protobuf |
|---|---|
| `:binary` | `bytes` |
| `:string`, `:immutable_string`, `:uuid`, `:email`, `:url`, `:symbol` | `string` |
| `:big_decimal`, `:decimal` | `string` (exact: `19.9`) |
| `:date` | `string` (`2026-11-01`) |
| `:boolean` | `bool` |
| `:integer` | `int64` |
| `:float` | `double` |
| `:time`, `:datetime` | `.google.protobuf.Timestamp` (the `zone:` offset is restored on decode) |
| `:value` | `.google.protobuf.Value` (numbers come back as Floats) |
| a struct class | its message |
| `:array, of: X` | `repeated` X |

Every singular scalar is `optional` (explicit presence), so an unset field reads back `nil`, not `0` or `""`. An unset
`:array` reads back `[]`: empty and unset are the same on the wire.

## Messages

`message_class` builds the class's message once and registers it with `google-protobuf`'s generated pool; `to_message` and
`from_message` convert one instance.

<!-- doctest -->
```ruby
require 'field_struct/protobuf'

module Velo
  class Station < FieldStruct::Base
    required :district, :string, proto: {number: 1}
    optional :dock,  :string, proto: {number: 2}
  end
end

message = FieldStruct::Protobuf.to_message(Velo::Station.new(district: 'Harbor'))
message.district # => "Harbor"
message.has_dock? # => false
FieldStruct::Protobuf.message_class(Velo::Station).equal?(message.class) # => true
FieldStruct::Protobuf.from_message(Velo::Station, message) # => Velo::Station.new(district: 'Harbor')
```

Field names in the message are the `serialize :protobuf` names, unconverted. Pass `serialization:` to use another format's
names.

## Limits

- Registration is permanent and per process. Changing a class's fields after its message was built is not noticed (the stale
  message rejects the new field); code reloading needs a restart.
- A class registers with one `serialization:` only; asking for a second raises.
- `decode` lets `Google::Protobuf::ParseError` through for malformed bytes.
- Integers past 64 bits raise `RangeError`.
